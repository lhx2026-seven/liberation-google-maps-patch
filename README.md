# 解放的Google Maps

首次使用只建立空白第 1 天；既有瀏覽器行程會保留。頁面會請求定位，允許後將空白地圖移至目前位置；拒絕或定位失敗仍可搜尋。定位僅用於本次地圖視角，不寫入行程儲存資料。

預設單指拖曳、雙指縮放（Maps JavaScript 模式）。預設使用有道路與地名標示的衛星圖，可在地圖右上切換地圖類型。點選地圖上的商家、景點或既有行程標記，可自動帶入新增目的地欄位，再按新增加入行程。Google 地點建議仍可輸入搜尋。若點擊沒有地點 ID 的車站圖示，在縮放層級 13 以上會使用 Places Nearby Search 查詢點擊位置周圍 60 公尺內的車站（此查詢可能計費）；一站直接帶入，多站列出供選擇。沒有站點結果時不更改目的地。此補救需要 Google 將點擊事件傳給頁面，未暴露點擊事件的圖示仍須搜尋站名。

滿版 Google Maps 與可收合行程工具：多日安排、自由新增停靠點、每段獨立交通方式、排序、裝置內儲存與匯出。

## GitHub Pages

1. 儲存庫 Settings → Pages → Build and deployment → Source 選擇 **GitHub Actions**。
2. 推送 main 或在 Actions 執行 Deploy GitHub Pages 工作流程。
3. 開啟 https://lhx2026-seven.github.io/liberation-google-maps-patch/ 。
4. 點「設定 Google Maps 金鑰」，在頁面內輸入金鑰。

金鑰應用程式限制設為「網站」，允許 `https://lhx2026-seven.github.io/*`；本機開發另加 `http://localhost:3000/*`。API 限制允許 Maps JavaScript API、Places API (New)、Routes API，專案必須已啟用這些服務並連結帳務。

金鑰只保留在本機瀏覽器 localStorage，不提交至 GitHub，不透過匯出行程分享。前端金鑰會被使用者看見，網站和 API 限制仍是必要保護。其他瀏覽器或裝置需各自設定金鑰。

未設定金鑰或 API 載入失敗時顯示明確連線狀態，不再悄悄退回無法畫行程的嵌入地圖；「重新連線」會沿用已存金鑰。設定後使用 Maps JavaScript、Places 與瀏覽器 routes 程式庫顯示標記、搜尋建議、各段路線、合計距離及時間。不需要後端或後端金鑰。

路線逐段查詢，因此沒有整日 waypoint 數量上限；每段都可能計費並受 Google 配額及所在地區交通方式支援限制。相同路線依預估出發時間的五分鐘區間，在本次頁面生命週期內重用查詢；刷新後重新查詢。每段在交通方式下方獨立顯示 Google 回傳的預估時間（不含停留）。每段另有紅、黃、藍、綠、橘、紫六色選單；顏色隨行程儲存在瀏覽器，改色直接更新線條，不額外呼叫路線 API。開車使用 TRAFFIC_AWARE 考慮路況，省略 departureTime 讓 Google 以伺服器現在時間計算，避免裝置時鐘差異造成 Timestamp 錯誤，大眾運輸按前段累計交通時間查詢出發班次。不提供日期時間設定，所有路線以現在出發（約一分鐘緩衝）與前段交通時間估算，不包含停留；舊版曾儲存的日期不再影響計算。手機行程面板採整體捲動，避免固定控制區壓縮路線內容。未自動定時刷新，修改行程或重新整理後更新。查詢部分失敗時保留成功路線並顯示提示，亦可逐段開啟 Google Maps。

## 天數管理

每天標題旁可用左右箭頭將當天往前／往後移動，選取狀態會跟著該天，地點、交通方式與顏色一起保留。最前與最後一天會停用無法移動的方向。「清空當天」確認後只移除當天停靠點，保留天數與其他行程；僅剩一天時也可清空。「刪除此日」仍只在至少兩天時提供。操作會自動儲存。

第 2 天起提供「帶入前一天終點」，把目前排序下前一天最後一站複製為當天第一站，保留地點 ID，不覆蓋既有停靠點；新接出的路段重新依距離決定交通方式。前一天沒有地點或當天起點已相同時停用，避免重複加入。這是一次複製，不會隨前一天後續修改自動同步。

## 自動交通方式

新增路段會先查詢 Google 步行道路距離：小於或等於 1,000 公尺預設步行，超過則預設開車；不是直線距離。查不到步行距離時暫用開車並提示。短程直接沿用步行查詢結果；長程會另查開車路線，因此可能增加 Routes API 用量。有手動標記的交通方式保留，不自動覆寫。舊版未記錄標記的步行路段會補上自動判斷，其他已存交通方式維持原樣。交通方式選單只顯示實際交通方式，系統查完距離後直接跳選步行或開車，不另設自動選項。自動路段更換地點或排序後重新判斷。

## 本機

Node.js 18 以上，無 npm 依賴。

```sh
npm start
npm run check
```

預設 port 3000，PORT 可覆寫。靜態發布只需 index.html、app.js、style.css。相對資源路徑支援 Pages 的儲存庫子目錄。

## 驗證範圍

語法檢查及 Chromium 模擬 Google API 測試已驗證金鑰設定流程、混合交通請求、切換交通方式、搜尋選點、空白天數與資料持久化。雲端網路封鎖 Google Maps / GitHub Pages，且未取得使用者金鑰；真實 API 回應與 Pages 發布狀態須在正式網址確認。本工具為獨立專案，非 Google 官方產品。

## 大眾運輸查詢限制

以選定的 Google 地點 ID 作為起訖點，按現在出發與前段交通時間查班次。Google API 回傳空路線不代表地點錯誤；可能是當時無班次或 API 地區資料與 Google Maps 網站不同。頁面會保留大眾運輸選項並提示使用「路線 ↗」到 Google Maps 查詢，不會改用開車或捏造時間。真實路段是否有資料須使用實際金鑰確認。

## 發布前回歸測試

`npm ci`、`npx playwright install chromium`、`npm test`。本機若已有 Chromium，可設定 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 後執行 `npm test`。GitHub Actions 會先執行瀏覽器回歸測試，再發布 Pages。測試使用模擬 Google SDK 驗證地圖連線、真正在地圖上掛載路線、滾輪縮放設定、距離選交通方式、時間與顏色、天數操作、金鑰保留與載入失敗重連；不代表真實 Google API 或正式站已驗證。
